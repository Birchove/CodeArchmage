# Code Archmage - 产品需求与架构蓝图

## 1. 产品定位与核心理念
**产品名称**：Code Archmage (代码大魔导师)
**产品形态**：独立的静态代码阅读器（推荐基于桌面端，或本地部署的 Web App）
**核心愿景**：降低复杂工程代码的认知负荷，帮助初学者跨越“从单文件算法到大型工程”的阅读鸿沟。
**目标受众**：初出茅庐、具备基本编程和算法基础，但在面对数万行、高度抽象与封装的工程项目时感到无从下手的计算机系学生或初级开发者。
**核心原则**：绝对只读、零环境配置、基于上下文的智能解析。

---

## 2. 竞品与类品分析

| 产品/品类 | 核心优势 | 对目标受众的痛点 | Code Archmage 的差异化定位 |
| :--- | :--- | :--- | :--- |
| **Source Insight** | 极速的静态解析，强大的符号跳转和关系图谱。 | 界面古老，缺乏 AI 辅助，学习成本高，对现代语言支持有限。 | 继承其强大的跳转与关联能力，配合现代化的 UI 设计与 AI 深度解释。 |
| **VS Code / Cursor** | 插件生态丰富，AI 代码生成与编辑能力强。 | 心智模型是“编辑器”。庞大的环境配置（LSP/编译器）容易导致满屏报错（红波浪线），极易让初学者分心。 | **做减法**。剥离所有编辑、编译、调试功能，提供零配置的“纯净阅读环境”。 |
| **Doxygen / 静态文档** | 结构化的 API 文档生成。 | 脱离了代码上下文，无法动态追踪变量，不适合用来“顺藤摸瓜”读源码。 | 提供动态追踪能力，AI 实时将代码逻辑转化为大白话文档，且保留代码上下文。 |
| **通用 LLM (ChatGPT/Claude)** | 解释能力强。 | 需要用户手动复制粘贴代码，丢失了工程的全局拓扑结构和依赖关系。 | **隐式 RAG (检索增强)**。底层自动拼装依赖树和符号定义作为 Prompt 发送给 LLM。 |

## 3. 核心功能模块定义

### 3.1 空间布局：三栏结构
*   **左侧栏 (The Map - 全局认知)**：
    *   **文件树**：标准的文件目录结构。
    *   **大纲树 (Outline)**：当前文件内的类、结构体、宏、函数的层级概览。
    *   **拓扑雷达**：选中某个核心类时，自动生成轻量级的 UML 依赖关系图或函数调用链 (Call Graph)。
*   **中栏 (The Scroll - 沉浸阅读)**：
    *   **纯享高亮区**：优质的代码高亮，**绝对不可编辑**。
    *   **无缝跳转与面包屑**：`Ctrl+Click` 跳转定义。顶部提供醒目的前进/后退历史路径，防止“迷路”。
    *   **透视镜 (Peek View)**：按下快捷键，在当前行下方展开小窗显示调用的函数源码，保持主线阅读不中断。
    *   **高光锚点 (Bookmarks)**：允许用户在代码行旁添加书签或“笔记”，便于二次复盘。
*   **右侧栏 (The Archmage - 智能解析)**：
    *   AI 助手的交互区，专注解答当前焦点代码的疑问。

### 3.2 智能解析核心场景 (AI 特性)
1.  **一键剥洋葱 (De-encapsulate)**：针对深层封装。选中一段调用，AI 结合底层实现，用直白的伪代码或文本总结其真实业务逻辑。
2.  **语法/范式解码 (Syntax Decoder)**：针对生僻语法（如 C++ 模板元编程、特殊的装饰器）。只解释语言特性，不涉及业务逻辑。
3.  **边界探测器 (Boundary Analyzer)**：提取复杂接口的前置条件 (Requires)、后置条件 (Ensures) 和异常处理逻辑。
4.  **算法步进翻译 (Algorithm Translator)**：将长篇的算法实现拆解为“初始化 -> 状态转移 -> 返回”的结构化文本文档呈现。

## 4. 严格的功能边界 (Do NOT Do)
*   **不做任何文本编辑**：避免处理撤销树、文件冲突、语法实时校验。
*   **不做编译与构建**：不要引入 CMake、Maven、npm 等构建工具的解析。
*   **不做终端与调试**：彻底放弃 Run / Debug 功能。
*   **不做通用聊天**：限制大模型的系统提示词，使其只能回答与当前代码库相关的架构、语法和逻辑问题。

## 5. 技术实现与架构设计

### 5.1 客户端技术选型
由于目标受众偏好沉浸式的文本阅读体验，且需要极高流畅度，推荐以下两种方案：
*   **方案 A (桌面端原生 - 推荐)**：基于 **C++ 与 Qt 框架** 构建。Qt 在处理本地文件系统加载、大规模文本渲染方面性能卓越，天然适合打造高性能的单机桌面应用。
*   **方案 B (Web 混合架构)**：Tauri (Rust) + Vue/React。前端使用 Monaco Editor (仅开启 ReadOnly 模式)，Tauri 负责本地文件的高速读取。

### 5.2 静态分析引擎 (代码解析)
放弃沉重的 LSP (Language Server Protocol)，转而使用 **Tree-sitter**。
*   **原因**：LSP 需要完整的编译环境配置才能精准跳转，对初学者极度不友好。Tree-sitter 基于增量解析生成抽象语法树 (AST)，即使代码有语法错误或缺失头文件，也能以极高的容错率提取出函数、变量、类定义，实现“零配置即时跳转”。

### 5.3 LLM 接入与上下文工程 (Agentic RAG)
这是 Code Archmage 的技术壁垒：
1.  **分层多 Agent 架构**：后台根据用户的操作调用不同的 Agent（如“语法解释 Agent”、“架构分析 Agent”），确保回答的专业度和聚焦性。
2.  **自动化上下文注入 (RAG Pipeline)**：
    *   当用户询问“这个函数在干嘛”时，底层自动通过 Tree-sitter 抓取该函数的完整实现体。
    *   抓取该函数内部调用的其他子函数的**签名 (Signatures)**。
    *   抓取所在类的**成员变量声明**。
    *   将这些代码片段打包组装成精准的 Prompt 发给 LLM，用户无需手动复制任何代码。

## 6. 演进路线
*   **Phase 1 (MVP)**：完成基于 Tree-sitter 的代码只读阅读器，实现文件树、高亮、快速跳转与透视窗。
*   **Phase 2**：集成 LLM API，实现右侧栏的“一键剥洋葱”和“语法解码”功能，跑通自动化上下文组装。
*   **Phase 3**：引入拓扑雷达和依赖图谱分析，完善本地阅读历史与批注功能。
