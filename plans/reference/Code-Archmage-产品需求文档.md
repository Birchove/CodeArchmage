# Code Archmage 产品需求文档

> 一个只做一件事的工具:帮初出茅庐的大学生,在陌生的、几万行代码的工程面前,建立起"我能看懂"的信心。

---

## 1. 问题定义与目标用户

**用户画像**:计算机专业在读本科生,懂基本的代码语法和算法(刷过一定量 LeetCode),但几乎没有阅读过"真实工程"。他们的困境不是"看不懂一行代码",而是"看不懂一行代码为什么被这样组织"——面对多层封装、抽象接口、陌生写法、复杂调用链时,缺乏拆解的方法论和工具支撑。

**四个具体痛点(用户原话归纳)**:

1. 满屏函数和类,封装之上还有封装,看不出具体作用
2. 遇到没接触过的代码格式/写法(装饰器、上下文管理器、依赖注入等)
3. 复杂的接口设计与边界检测(参数校验、异常处理、契约)
4. 关键算法本身难以从代码反推出思路

**产品目标**:给一个陌生代码仓库画出一张"可交互、可提问、可折叠"的地图,让用户能像剥洋葱一样,从"这个项目大概是干什么的"逐步拆到"这一行为什么这么写"。

**非目标**:不是 IDE,不是代码生成工具,不是团队协作平台,不是笔记软件。

---

## 2. 竞品全景与对比

在决定形态之前,先看清楚这个赛道里已经存在什么、都做对了什么、都留下了什么空当。

| 产品 | 形态 | 核心能力 | 现状 | 与 Code Archmage 的差距 |
|---|---|---|---|---|
| **Source Insight** | 独立桌面客户端 | 自建符号数据库,函数/变量/类的静态关联分析,速度极快 | 仍在售卖,但界面停留在上世纪,无 AI,几乎不支持现代动态语言的深层语义 | 只做"关联",不做"讲解";用户仍需自己理解为什么这么设计 |
| **Understand (SciTools)** | 独立桌面客户端 | 极强的静态分析 + 度量指标(圈复杂度等),偏安全关键/合规场景 | 仍在维护,面向企业和资深工程师 | 定位是"分析代码质量",不是"教新手读代码",界面密度对新手极不友好 |
| **Sourcetrail** | 独立桌面客户端(已停更) | 索引后交互式跳转 + 依赖图,C/C++/Java/Python | 2021 年停止维护,是这个品类里离"新手友好的可视化阅读器"最近的先例 | 证明了"可视化索引阅读器"这个形态是成立的,但没有 AI 讲解层,项目已死 |
| **Sourcegraph / Cody** | IDE 插件 + Web | 跨仓库代码搜索、AI 问答、企业级上下文检索 | 活跃,但定位是"帮资深工程师在大厂多仓库里高效工作" | 面向生产力而非学习,没有"折叠抽象""标注陌生写法"这类教学向设计 |
| **CodeSee** | Web(浏览器插件 + 网页) | 自动生成代码地图、Code Tour 引导式讲解、PR 影响可视化 | 已被 GitKraken 收购,独立产品下线,团队功能拆分转移 | 证明"Code Tour 式引导阅读"是刚需,但它面向团队协作/新人 onboarding,不面向个人自学一个陌生开源项目 |
| **Swimm** | IDE 插件 + Web | "活文档":团队手写的代码讲解会随代码变化自动跟踪更新 | 活跃,承接了部分 CodeSee 用户 | 文档需要项目维护者手写,不是自动拆解任意仓库给自学者用的工具 |
| **DeepWiki (Cognition/Devin)** | Web(纯只读) | 把任意 GitHub 仓库自动生成带架构图的 Wiki + AI 问答,免费公开仓库可用 | 2025 年上线后迅速流行,已索引 5 万+ 仓库 | **目前最接近 Code Archmage 的产品形态**,但它是"生成一份文档给你看",偏静态阅读、偏宏观架构;缺少逐符号跳转、逐函数折叠展开、"陌生语法自动标注"这类颗粒度更细的教学交互,且不可控——用户无法针对自己的理解程度调整拆解深度 |
| **VSCode/Cursor 内建导航 + Copilot Chat** | IDE 内置 | 跳转定义、查找引用、内联 AI 问答 | 主流工程日常工具 | 是"工作模式"而非"学习模式",没有难度分层、没有引导路径、没有为新手做的降噪设计 |

**结论**:这个赛道分成两条线——

- **静态分析派**(Source Insight / Understand / Sourcetrail):关联做得深,但没有语义讲解,门槛高
- **AI 文档派**(DeepWiki / Swimm / CodeSee):讲解做得好,但停留在"整体架构介绍"层面,缺少逐层深入、按需展开的**颗粒度控制**,也没有专门为"新手第一次读工程代码"设计的降噪交互

Code Archmage 的空当在于:**把静态分析派的精确符号级关联,和 AI 文档派的语义讲解能力,叠加在一个专为"新手逐层拆解陌生代码"设计的折叠式阅读器上**,并且明确只服务个人自学场景,不做团队协作、不做工程管理。

## 3. 产品形态决策

**结论:独立的只读 Web App,技术上按桌面应用(Tauri)预留退路。**

不做 VSCode/Cursor 插件的原因已在前一轮讨论中定论,这里补充在竞品分析之后更明确的两点:

1. DeepWiki 已经验证了"贴一个仓库链接 → 生成可读文档"这个路径的可行性和受欢迎程度,说明用户愿意脱离 IDE、进入一个专门的阅读场景——这反过来支持"独立 Web App"而非"插件"的判断。
2. 但 DeepWiki 的交互颗粒度停在"整篇讲解",Code Archmage 要做的是比它更细一级的"可折叠符号级阅读器",这种细粒度的折叠/展开/局部图谱交互,在浏览器里用标准 Web 技术(而非 IDE 插件框架的限制性 API)反而更容易做得灵活。

**为什么不完全照抄 DeepWiki 的"生成一篇文档"模式**:文档是线性的,读者被动接受作者(AI)组织内容的顺序。而 Code Archmage 强调的是用户按自己的困惑点主动折叠/展开/提问——地图感,而不是文章感。这是两者定位上最本质的差异。

**部署形态选择**:

- **第一阶段:纯 Web App**。用户粘贴 Git 仓库地址或上传本地代码压缩包,后端克隆/解析/建索引,前端展示。零安装成本,验证核心体验最快的路径。
- **第二阶段(视验证结果决定是否做):Tauri 打包桌面版**。面向需要分析私有仓库、不想上传代码到云端的用户,本地跑索引和 LLM 调用(或本地起 FastAPI 服务连本地模型/API Key)。

## 4. 核心功能模块详述

### 4.1 仓库接入与索引

- 输入方式:Git 仓库 URL(公开仓库直接 clone)、上传本地代码压缩包
- 索引范围可控:允许用户排除 `node_modules`、`vendor`、测试目录、生成代码等噪音目录,索引前给出"建议排除清单"(基于常见 `.gitignore` 模式和目录规模)
- 索引是"快照式"的,不做实时增量跟随。用户可以手动"重新索引",而不是让工具在后台一直盯着文件变化

### 4.2 文件树(结构层)

- 常规树形结构基础上,叠加"重要性标记":自动识别入口文件(如 `main.py`、路由注册文件、CLI 入口)与高被引用文件,做视觉权重区分
- 支持按"模块"聚合视图,而不仅是物理目录——很多工程的目录结构和逻辑模块并不完全对应,后续可以基于调用图做聚类,给出一个"逻辑分组"视图作为物理目录树的补充(非 MVP 必做,列入二期)

### 4.3 代码阅读主视图

- 只读、语法高亮(基于 tree-sitter 做多语言解析,不依赖语言官方 LSP 以降低集成成本)
- 符号跳转:点击函数/类名跳转定义;反向查看"谁调用了我"
- **默认折叠**:函数体默认折叠,只显示签名 + 一句话摘要(优先取 docstring,没有则用 LLM 生成),按需展开——这是解决"封装之上还有封装"问题的核心交互,也是与 DeepWiki 式"整篇文档"最大的体验差异
- 悬浮提示:hover 一个符号给出简短语义解释,不用跳转打断阅读流

### 4.4 调用关系图谱(局部展开,不做全局大图)

- 以当前函数/类为中心,默认只展开上下游各 1-2 层
- 用户可以点击图上的节点继续扩展,而不是一进入就看到几百个节点的蜘蛛网——这是刻意针对"满屏封装很吓人"痛点的克制设计
- 图谱节点可直接点击跳回代码视图,双向联动

### 4.5 全局符号搜索

- 按名称/模糊搜索快速定位函数、类、变量定义,支持按类型(函数/类/变量/常量)过滤

### 4.6 内嵌 LLM 问答面板

- 默认上下文注入:自动把当前打开文件、当前展开的函数、用户选中的代码片段作为上下文喂给模型,用户不需要手动复制粘贴
- 支持"选中一段代码 → 提问"的快捷交互
- 支持针对某个符号发起"综合解释"请求:自动检索该符号的定义 + 主要调用点,组织成结构化解释(定义做什么、被谁在什么场景下调用、常见的调用参数模式)——这部分可以直接复用你在 hindsight 项目里已经在做的 RAG 检索架构
- 问答历史与当前阅读的文件/符号绑定,方便回看"我当时为什么问这个"

### 4.7 陌生语法/写法自动标记

- 扫描 AST,识别装饰器、上下文管理器(`with`)、生成器/协程、元类、依赖注入模式、类型泛型等"新手大概率没见过"的写法,打标签
- 标签可点击,弹出简短讲解(优先用预置的语法知识库,而非每次都现调 LLM,降低成本和延迟;知识库覆盖不到的写法再触发 LLM 现场解释)

### 4.8 接口契约与边界高亮

- 对函数的参数校验逻辑、异常抛出点、前置/后置条件做规则提取 + 视觉高亮
- 目标是让用户一眼看到"这个函数对输入有什么要求、出错会怎样",而不需要通读整个函数体去猜

### 4.9 关键算法标记与分步讲解

- 允许用户(或系统启发式识别,例如包含双重循环+状态更新的函数)标记某函数为"核心算法"
- 触发更详细的分步讲解模式:按代码执行顺序拆解成若干步骤,每步给出目的说明,必要时配合伪代码,而不是简单地把整个函数体丢给 LLM 生成一段话复述

### 4.10 个人标注层

- 用户自己的高亮/笔记,与 AI 生成的解释在视觉上分层显示,不混淆"这是我的理解"和"这是 AI 说的"
- 提供轻量的"已理解 / 仍困惑"标记,用于自己追踪阅读进度
- 明确不做完整笔记系统,不支持双链、不支持复杂标签体系——需要更强笔记能力时,用户自己导出到 Obsidian

### 4.11 引导式阅读路径(二期功能,不列入 MVP)

- 基于依赖图自动生成建议阅读顺序(从入口文件按拓扑排序展开)
- 或允许项目维护者/资深用户手写一条"新手阅读路线",这个方向如果做起来会让产品有一定的 UGC/分享属性,但会显著扩大范围,MVP 阶段刻意不碰

## 5. 技术架构草案

```
┌─────────────────────────────────────────┐
│  前端 (Web / 未来 Tauri 壳)                │
│  - 代码渲染 + 折叠交互 (CodeMirror/Monaco)  │
│  - 调用图谱可视化 (d3.js / react-flow)      │
│  - LLM 问答面板                            │
└───────────────┬─────────────────────────┘
                │ REST / WebSocket
┌───────────────▼─────────────────────────┐
│  后端 (FastAPI)                           │
│  - 仓库拉取/上传处理                        │
│  - tree-sitter 解析 → 符号表 + AST         │
│  - 调用图构建 (静态分析)                    │
│  - RAG 检索层 (复用 hindsight 架构)         │
│  - LLM 网关 (摘要生成/问答/语法讲解)         │
└───────────────┬─────────────────────────┘
                │
        ┌───────▼────────┐      ┌──────────────┐
        │ PostgreSQL      │      │ 向量库         │
        │ 符号表/调用关系/  │      │ (代码片段/     │
        │ 用户标注         │      │  语义摘要 embedding) │
        └─────────────────┘      └──────────────┘
```

- 解析层用 tree-sitter 而非各语言官方 LSP:LSP 集成成本高(每种语言要起一个 language server 进程),tree-sitter 只需要语法层解析即可满足"符号定义+跳转+高亮"的需求,牺牲一部分类型推导精度换取工程简洁度,符合"小而精美"的定位
- MVP 阶段语言支持仅锁定 **Python**,理由:目标用户(计算机/生物信息背景大学生)接触最多的入门语言是 Python,且你自身技术栈(hindsight 项目)已经在 Python 生态里,复用度最高
- LLM 调用走网关层统一管理,预留多模型切换能力,不锁死在单一供应商

## 6. MVP 范围界定

**MVP 必须包含**(对应上面 4.1-4.6):

1. 仓库导入与索引(仅 Python)
2. 文件树 + 重要性标记
3. 代码只读阅读视图 + 符号跳转 + 默认折叠
4. 局部调用关系图谱
5. 全局符号搜索
6. 内嵌 LLM 问答(带自动上下文注入)

**MVP 之后视验证结果排期**(对应 4.7-4.10):

- 陌生语法自动标记
- 接口契约高亮
- 关键算法分步讲解
- 个人标注层

**明确列入二期或不做**:

- 引导式阅读路径 / UGC 阅读路线
- 多语言支持扩展
- 逻辑模块聚合视图(区别于物理目录)
- 桌面应用打包

## 7. 明确要做 / 不要做(收敛版)

**要做**:

- 只做"理解已有代码"这一件事:解析、索引、跳转、折叠、摘要、问答、标注
- 只读,不可编辑、不可运行、不可调试
- MVP 锁定 Python 单语言
- 单用户学习工具,不做团队功能

**不要做**:

- 不做代码生成/自动补全,避免滑向 Copilot 赛道
- 不做版本控制、PR review、团队评论等协作功能
- 不做"万能多语言解析器"的野心,深耕一种语言优先于覆盖十种语言
- 不做实时增量索引跟随用户编辑,仓库按快照处理,按需重新索引
- 不做通用笔记管理系统,标注功能保持轻量
- 不做团队级"活文档"(Swimm 的方向)、不做工程指标看板(CodeScene/Understand 的方向)、不做整篇线性 Wiki(DeepWiki 的方向)——这三个方向都有成熟玩家占位,Code Archmage 的差异化就在于"个人向、折叠式、颗粒度可控的符号级阅读器"这一个窄位置

---

## 8. 一句话定位

**Code Archmage 是给"看得懂算法题、看不懂真实工程"的学生准备的一把放大镜:把任何一个陌生仓库,拆成一张可以逐层展开、随时提问的地图,而不是又一份要从头读到尾的文档。**
